Changelog

What changed in each version of peek. To update a machine, run npm update -g @peculiarnewbie/peek there, then peek install again.

0.4.222 November 2026Latest

Changed

  • Smoother video and faster soft-motion restore: live motion now takes priority over sharpening so high-FPS video cannot stall on full-quality refine frames, fragmented video regions coalesce into fewer JPEG rectangles, congested links adapt pipeline depth and moving quality from excess queueing delay, and soft tiles sharpen in about 100 ms once still (with tiny typing and hover updates staying sharp immediately).

0.4.122 November 2026

Changed

  • Faster Windows connects: connecting to an idle Windows machine shows its screen in under 50 ms instead of about 250 ms, by showing a screenshot while screen capture starts.
  • Faster, sharper screen streaming: compact lossless WebP encoding (smaller text updates and first frames), damage-region capture and alpha-masked diffing, averaged 4:2:0 JPEG chroma, overlapped browser decoding, physical-pixel canvas alignment, and lower-latency pointer and scroll input.

0.4.021 November 2026

New

  • Check for updates and restart on demand: Settings now offers Check for updates and Restart peek, and the Machines page offers Check for updates and Update all across online machines. peek restart restarts the running host from a terminal.
  • Plugin scaffolding, page SDK, and linked installs: peek plugin init <name> creates a runnable JS or Python starter plugin with a page powered by the built-in /p/_sdk.js helper, and peek plugin add --link <dir> runs a local plugin folder in place without copying it.
  • Bearer auth on HTTP APIs: provider, plugin, frame-ticket, update, and restart endpoints now accept Authorization: Bearer <token> in addition to a JSON body token.

Changed

  • Stateless frame tickets: plugin page tickets are now signed with HMAC-SHA256 using the host's local secret, so open pages survive host restarts and self-updates.
  • Safer Windows service default: when peek runs as the Windows SYSTEM service, browser-driven plugin installs default to off (peek plugin remote-install on turns them back on).
  • The direct machine-served page now reloads automatically after a self-update completes, and restarting stops running provider processes cleanly before handing off.

0.3.118 November 2026

New

  • peek updates itself: from this version on, when a newer one is out, a machine's card and its Settings say so and offer Update. The machine downloads it, checks it against the release's checksums, and restarts on it. peek update does the same from a terminal there, and peek update --rollback goes back. This update itself still goes through npm.
  • Plugins on every machine, side by side: Plugins, beside Machines at the top of your list, shows which plugins each machine has. Turn one on or off anywhere, install one where another machine got it, and update an older copy. Each machine's card shows its plugins and has a button straight to its Plugins page. A machine needs peek 0.3.1 to show up there. Apps and plugins.
  • Processes: a fourth app that comes with peek, off by default. It lists what is running with its processor and memory use, and ends a program after asking. By default it ends only your own programs.
  • Images on the clipboard: Ctrl+V sends an image you copied to the machine, and an image copied there reaches the browser, up to 8 MB each. Clipboard images in Settings turns it off. Over plain HTTP it works for pasting only.
  • Pair without Tailscale: peek pair on a machine with no Tailscale now gives a link to the machine's own page at its addresses on your network, instead of failing.

Changed

  • peek install keeps its flags. Run with no flags, it keeps those of the last install, where before it dropped them, --view-only included. Flags after it replace them, and peek install --defaults goes back to none. It says which flags are in effect.
  • Losing the connection: the picture dims while it is not live, and a machine's own page says when it cannot reach the machine. A message that will not go away by itself has a Retry button. Keys are left to the browser meanwhile, so F5 and Ctrl+R reload.
  • When a machine runs a different version of peek than this site, the message links to the machine's own page, which always matches it.
  • What a plugin writes as errors is kept in its log, and peek's log says when a plugin's output is not what peek expects. A plugin cannot take the name of an app that comes with peek, and the error says so.
  • Power is off by default, like Files. An install that never changed it loses it on updating; turn it on under Settings → Manage plugins.
  • The toolbar's Sleep is now Pause, and the status says Paused: it pauses the picture in this browser, while Power's Sleep puts the machine to sleep.
  • Adding a machine by a short name or an address says what to type instead: its full Tailscale name, as peek pair prints it, or for an address, the machine's own page at http://<address>:9182/.
  • The addresses peek prints when it starts are labelled (this machine, your network, Tailscale), and leave out the bridges of containers and virtual machines (Docker, libvirt, WSL and the like), as the pairing links of peek pair do.
  • peek pair says when it sets up Tailscale Serve, and the command that undoes it. Its QR code is left out when the output goes to a pipe or a file; the link stays.
  • While a machine's screen shows, the tab's title is the machine's name, here and on the machine's own page.
  • peek provider add and remove start and stop the provider in the running peek, as peek plugin does, with no restart.
  • A machine's card gives its name the card's whole width, and the full name shows on hovering it. An offline machine's card and the Plugins overview show the plugins it had when last seen, faded and marked with when that was, instead of only "offline".
  • The Plugins overview's By plugin layout can turn a plugin off on a machine, not only on.
  • peek -h is short, a line for each command and flag; peek --help and peek <command> --help give the detail.
  • The prompt for a pairing code names the machine, and a visitor refused with --no-token is told why instead of getting an empty page.

Fixed

  • The browser's pointer and clicks stay aligned with the remote screen after the display resolution changes.
  • On Linux, peek restarts on the version it just installed after a self-update.
  • With a plugin's page open over a machine's screen, mouse, wheel and touch went to the frozen screen behind it and clicked on the machine unseen. They are ignored now, as keys already were.
  • A plugin that names its page by a path relative to its folder ({"page": "page"}) gets it served, where before it opened a 404. A page folder that is not there gives no button, and peek's log says why.
  • peek uninstall said it had removed peek when nothing was installed. It says so now, and if Tailscale Serve still passes to peek, it prints the command that removes that.
  • A flag of peek's given after a command, like peek pair --no-token, failed with no hint. The error now says the flag goes before the command, and shows the command line that works.
  • Starting peek a second time on the same port says that peek already runs there and how to pick another port, before starting anything, instead of failing with "Address already in use".
  • The access token's file could be read by other users of the machine (Linux). It is private now, and an existing one is made private when peek starts.
  • Pasting text could stop working until the page was reloaded.
  • The ✎ keyboard button on a phone pressed Enter on the machine.
  • With a Mac keyboard, Cmd with a letter typed that letter on the machine. Cmd+V now pastes there.

0.3.015 November 2026

New

  • More than the screen. Three apps come with peek:
    • Vitals: processor, memory and storage, as a line on each machine's card and as figures in the stats panel.
    • Power (Windows): Sleep on a machine's card, and Wake while it is asleep, sent by another paired machine on the same network. The first sleep is a test: the machine is woken 15 seconds later, and the card says what to check if it was not.
    • Files: browse folders you choose and download from them. Off by default; turn it on under Settings → Manage plugins.
    An app with a page of its own gets a button in the toolbar.
  • Plugins: Settings → Manage plugins installs a plugin from a folder, a .tgz, a git address or npm, and starts, stops, updates and removes it without restarting peek. A plugin runs with peek's rights (SYSTEM under the Windows service), so install only ones you trust. How to write one.
  • Windows service: connections stay open through a sign-out and a switch of user. The picture stops for a few seconds and comes back on the login screen, with nothing to reconnect. After updating, run peek install --service again.
  • Pair from a machine's own page: peek pair and Settings → Pair a device also give a link to the page the machine serves itself, which asks for the code when it has no token. This works with --web none too.
  • A favorite machine: star a machine's card, and the installed app's Favorite shortcut opens it directly.

Changed

  • The installed app opens in a window of its own instead of full screen, so Android's system bars stay. The toolbar's full-screen button still hides them.

0.2.212 November 2026

New

  • Share Tailscale Serve with another app: peek pair --serve-port 8443 (or 10000) reaches peek on that HTTPS port when another app, like T3 Code, has 443. Pairing links and codes name the port, and later peek pair runs find it by themselves. Without the flag nothing changes.

0.2.112 November 2026

New

  • One command to try peek: npx @peculiarnewbie/peek pair. If peek is not running yet, peek pair now starts it in that terminal and then shows the pairing link and QR code. peek keeps running there until you close it; peek install still starts it at logon instead. Pair a browser.

0.2.012 November 2026

New

  • Windows: the login screen, the lock screen and UAC prompts. peek install --service runs peek as a Windows service, which can also see and control these, and keeps peek running while nobody is signed in. A paired browser can then do there whatever someone at the keyboard could. How to set it up.
  • Lossless text, in Settings and on by default: text and flat parts of the screen arrive exact the first time, instead of blurry and then sharp a moment later. Photos stay JPEG. Typing a character sends 238 bytes instead of 1.7 KB, and a full screen of code 84 KB instead of 219 KB. It needs peek 0.2.0 on the machine.

Fixed

  • When many scattered parts of the screen changed at once, some could stay blurry until they next changed. They are now sharpened like the rest.

This site

  • A machine's page is now at /screen/<name>. Old addresses and bookmarks still lead to it.
  • This changelog.

0.1.011 November 2026

The first release on npm.

  • A host for Windows, and for Linux on Wayland (niri, sway, Hyprland, river), that stays idle until someone looks. Any browser is the client.
  • This site: one page for all your machines, each paired once with peek pair and reached straight over Tailscale.
  • peek install starts peek at logon (Windows, as administrator, with a firewall rule) or with the graphical session (Linux). peek uninstall removes it.
  • peek logs shows what the running peek logged. peek clients and peek unpair manage paired browsers.
  • On phones and tablets: trackpad and touch modes, and a keyboard bar with a PC keyboard.
  • Windows: capture comes back after the PC wakes from sleep, and --keep-gpu makes connecting from idle faster.
