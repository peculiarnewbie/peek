peek is a remote desktop for your own machines that connects instantly. The machine runs a small host that stays idle until you look; any browser is the client. It is meant for the times you want another computer's screen for a few seconds, where a five-second connect would be most of the wait.

How it works

  • The host runs on Windows, or on Linux under a Wayland compositor with the wlroots protocols (niri, sway, Hyprland, river). It captures the screen only while a client is watching.
  • This site serves the page and nothing else. Your browser connects straight to each machine over Tailscale, at its https://<machine>.<tailnet>.ts.net name.
  • The list of your machines and the keys for them stay in your browser. Nothing about them is sent to or stored on this site.

Numbers

What matters for a quick look is how long the screen takes to appear, so that is what peek is built around. All at medium quality.

Over Tailscale

From a Linux laptop to a Windows desktop (one 1920×1080 screen) on another network, connected directly with a ping of about 8 ms, peek started with --keep-gpu:

MedianSlowest 10%
Connect to an idle machine, until the whole first frame (331 KB) has arrived125 ms157 ms
The same within 5 seconds of the last connection, capture still set up121 ms157 ms
Of that, capturing and encoding the full screen11 ms15 ms
Socket open (WebSocket handshake answered)15 ms18 ms

Most of the rest is carrying the frame: the more detail on the screen, the bigger it is and the longer it takes. Without --keep-gpu, starting from idle added about 200 ms on this machine.

On the machine itself

A Linux laptop (niri, one 1920×1080 screen) connecting to its own peek, so these are peek's own share of the wait:

MedianSlowest 10%
Connect to an idle machine, until the whole first frame (149 KB) has arrived24 ms26 ms
The same within 5 seconds of the last connection, capture still set up14 ms18 ms
Of that, capturing and encoding the full screen13 ms14 ms
Socket open (WebSocket handshake answered)1.3 ms1.6 ms

While nobody is looking, peek captures nothing: over two idle minutes it used 10 ms of CPU time (0.01% of a core) and held 17 MB of memory. The program is 3.6 MB.

The browser then takes a few milliseconds to decode and draw the frame. To see your own total, open Stats: First frame is the time from connecting to the screen drawn in your browser. To repeat these measurements, run bun bench/first-frame.ts from the repository (its header says how).

Set up a machine

1. Tailscale

Install Tailscale on the machine and on every device you will view it from, all on the same tailnet. Then, once per tailnet, in the Tailscale admin console under DNS, turn on HTTPS Certificates. (This puts your machine and tailnet names in the public Certificate Transparency logs.)

2. Install peek

peek is on npm, for Windows x64 and for Linux x64 and arm64. With Node installed:

npm install -g @peculiarnewbie/peek

bun add -g @peculiarnewbie/peek and pnpm add -g @peculiarnewbie/peek work too. Node only starts peek; the package carries the program itself.

To try it first without installing anything, run npx @peculiarnewbie/peek pair and go on to Pair a browser. peek then runs in that terminal until you close it.

3. Start it at logon

peek install --no-token

This copies peek to a fixed place and starts it in the background whenever you log in. Flags after install are for that peek; --no-token means only Tailscale connections are accepted.

Windows asks once for administrator rights: peek is allowed through Windows Firewall (Tailscale addresses only) and started hidden and as administrator, so it can also control windows that run as administrator. On a desktop PC, add --keep-gpu to connect faster from idle: peek then keeps its GPU device open while nobody is watching. It costs some memory, and on a laptop it can keep a separate graphics card from sleeping, so it is off by default.

Windows, at the login screen too: peek install --service --no-token runs peek as a Windows service instead. It then also shows the login screen, the lock screen and UAC prompts and takes input there, and keeps running while nobody is signed in, so a paired browser can do there whatever someone at the keyboard could. Turn on Run unattended in Tailscale's settings on that PC, or Tailscale disconnects while nobody is signed in. peek install without --service goes back; either way your paired browsers keep working.

Linux: run it from inside the Wayland session. It becomes a systemd user service that starts with the graphical session. Keys are typed through /dev/uinput, which many distributions already let the logged-in user write; the README has the one-line udev rule if yours does not.

After updating (npm update -g @peculiarnewbie/peek), run peek install again with the same flags. peek uninstall removes it. To build from source instead, see the README.

Pair a browser

On the machine, run:

peek pair

The first time, it sets up Tailscale Serve so browsers can reach the machine over HTTPS (Tailscale may ask you to allow that, or on Linux for sudo tailscale set --operator=$USER). If peek is not running yet, it starts peek in that terminal, which keeps it running until you close it. Then it prints a link and a QR code with a one-time code, valid once, for five minutes. Then either:

  • open the link on the device you want to use, or scan the QR code with its camera (on Android Chrome, Scan QR code on this site works too), or
  • on this site, choose Add a machine and enter the machine's name and the code.

A browser already connected to the machine can pair another device too: Settings → Pair a device shows a QR code.

Tailscale Serve's usual HTTPS port, 443, can go to only one app on a machine. If another app has it, peek pair says so and leaves it alone. peek pair --serve-port 8443 (or 10000) puts peek on another port instead. The machine's name then includes the port, like my-pc.tail1234.ts.net:8443, and the link and code from then on carry it.

In Chrome, allow Local network access when the site asks. Without it Chrome blocks the page from reaching your machines.

Using it

Open a machine from your list. Its page has its own address (for example /screen/my-pc), so it can be bookmarked; the toolbar's back button returns to the list. Hover the dot at the top for the toolbar.

  • Sleep stops the screen while keeping the connection; click the page or press Space to resume. Pause when unfocused in Settings does this whenever the window is in the background.
  • Settings has presets (Saver, Balanced, Crisp), and quality, resolution, motion, frame rate and monitor on their own.
  • Stats shows frame rate, data rate and latency.
  • Mouse, keyboard and clipboard go through as on the machine itself.

Paired browsers

On the machine:

peek clients        # list the browsers paired with it
peek unpair <id>    # unpair one; it can no longer connect

On this site, the × on a machine forgets it in this browser. Pairing it again needs a new code.

Security

  • Machines are reached only over Tailscale, so your tailnet decides which devices can get to them at all.
  • From this site, a machine accepts only browsers paired with it. Each browser has its own key; the machine keeps only a hash of it.
  • Pairing codes work once, for five minutes, and guessing is rate-limited.
  • Never expose peek's port with tailscale funnel: that would put it on the internet.

Troubleshooting

"Cannot reach" a machine

  • Check that Tailscale is connected on this device and that the machine is on.
  • Check that peek is running there and that peek pair set up Tailscale Serve (tailscale serve status).
  • In Chrome, check the site may access your local network: the icon left of the address bar.
  • The very first connection to a machine can take a few seconds while Tailscale fetches its certificate.

Seeing what peek is doing

On the machine, peek logs shows what peek logged recently (connections, capture starts, errors), even when it runs in the background; peek logs -f keeps following it.

"No longer paired"

The machine unpaired this browser, or its pairing data was reset. Run peek pair there again.

Everything else, including every option and how peek works inside, is in the README on GitHub.
